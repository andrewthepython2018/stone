# Веб-версия: программа по ссылке в браузере

Заказчик открывает ссылку, загружает фото и получает тот же результат, что и в
программе для Windows: ковш ищется автоматически, можно обвести контур, задать
эталон и масштаб, переключить «учитывать мелочь», скачать отчёт (zip:
`results.csv`, `granulometry.png`, `overlays/`). Устанавливать ничего не нужно,
работает и с телефона.

Расчёт идёт на сервере тем же кодом (`foto/analyze.py`, `fragmentation/`).
Фото хранятся только в памяти сервера, пока с ними работают (не дольше 3 часов
без обращений, не больше 60 фото на всех), на диск не пишутся.

## Запустить у себя

```
pip install -r requirements-web.txt
python -m web                 # http://127.0.0.1:8000
```

## Настройки (переменные окружения)

| переменная | что задаёт | по умолчанию |
|---|---|---|
| `ACCESS_CODE` | пароль на страницу (браузер спросит имя и пароль, имя любое) | нет пароля |
| `PORT`, `HOST` | порт и адрес | 8000, 127.0.0.1 (в Docker 7860, 0.0.0.0) |
| `FOTO_WORKERS` | сколько фото считаются одновременно | ядер − 1, не больше 4 |
| `FOTO_CACHE`, `FOTO_TTL` | сколько фото держать в памяти и сколько секунд | 60, 10800 |

## Размещение

**Docker** (любой сервер или VPS, 2 ядра и 2–4 ГБ памяти достаточно):

```
docker build -t kuskovatost .
docker run -d --restart=always -p 80:7860 -e ACCESS_CODE=пароль kuskovatost
```

**Hugging Face Spaces** (бесплатно, CPU basic: 2 ядра, 16 ГБ). Docker-Space там
платный, поэтому создаётся Space с SDK **Gradio** (Blank, CPU basic, Public), и в
него загружаются `app.py`, `requirements-web.txt` под именем `requirements.txt`,
папки `fragmentation`, `web`, `primery` и `foto` (достаточно `__init__.py` и
`analyze.py`). `app.py` запускает этот же сервер на порту 7860. Пароль задаётся
секретом `ACCESS_CODE` в настройках Space.
